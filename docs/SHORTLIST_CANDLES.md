# Shortlisted stocks, full candles and five-second paper workflow

Open http://127.0.0.1:1111/workspace/automation and connect the workspace.
The Shortlisted stocks · candles and AI panel shows up to three news-selected stocks before any fill.

Each card contains a candlestick chart, OHLCV details, RSI and VWAP, news direction, entry qualification, actual fetch/AI-response times, candle counts and an all-candle CSV download. Select the latest 75, latest 150 or all candles for display; AI receives the same full history regardless of chart range. Green/red candles show close versus open. Green/red/amber evidence badges show bullish/bearish/neutral or stale analysis. Actual paper BUY and SELL dots are drawn only from recorded fills; a bullish badge is not an entry approval.

The history scope is all valid completed five-minute candles returned by Groww in the configured rolling 14-day window, up to the existing 5,000-bar contract limit. It is not unlimited all-time data. Invalid, duplicate and unfinished rows remain excluded by existing normalization. Missing data is not fabricated. The automatic order strategy retains its 100-bar warm-up and all configured risk gates.

A single server worker checks about every five seconds, reloads the shortlisted histories and sends them with the maintained NIFTY/50-stock context to Trading AI. Context histories are cached within a five-minute bucket; shortlist histories refresh each eligible cycle. AI returns a selection or NO_TRADE. A selected BUY/LONG or SELL/SHORT goes to final decision evaluation with a fresh quote; Java independently approves/rejects one simulated order. Per-five-second idempotency and the existing one-position transaction lock prevent duplicate/concurrent entries. Network latency, worker duration and throttling can extend the interval; cycles never pile up. Failed data/service attempts back off 30 seconds.

When a position exists, full candle reviews continue via /api/v1/analysis/stock; the selector cannot open another stock. Existing quote-based position events also continue about every five seconds. Candle reviews do not alter the fixed target, stop or independent exit rules. Local P&L/risk monitoring and 14:59 IST exits remain authoritative. Real broker execution remains disabled.

GET /api/v1/auto/shortlist is authenticated and cache-only. It returns stock bars, actual-fill markers, analysis/count acknowledgments, entry-check reasons, fetched/AI timestamps and freshness metadata. Reading charts never creates an order or calls Groww.

An isolated authenticated HTTP test sent 775 candles for each of three news candidates, verified all 775 analyzed, selected one paper SELL/SHORT, and received BUY-cover advice at target. No Groww or real orders were used by that test.

Live adapter correction: observed Groww responses use epoch seconds for last_trade_time and can omit scalar bid/offer while providing depth.buy/depth.sell. The adapter supports plausible epoch seconds and milliseconds and uses the best actual positive-quantity depth level when scalar prices are absent. Missing book sides remain unavailable; no price or depth is invented. Existing stale/future, crossed/spread, quantity and instrument checks still apply. The published schema documents milliseconds and the depth structure: https://groww.in/trade-api/docs/curl/live-data . This compatibility handling follows the observed response rather than replacing timestamps with receipt time.

Storage: trader audit events now keep compact identifiers, actions and reasons rather than duplicating full candle histories. Java status omits the selected request's raw NIFTY/sector arrays after evaluation; full inputs still reach AI and full AI selection records remain in its store. Explicit Oracle CLOB binding supports large retained evidence. Live verification found ORA-01536 on the local GROWW_TRADER schema: 97,845,248 bytes allocated against a 104,857,600-byte quota. Existing trading/audit data was not deleted. After compact-record deployment, live pause and repeated analysis writes succeeded within the unchanged 100 MB quota. Paper automation was restored. The quota increase is no longer required for this update and was not executed.
